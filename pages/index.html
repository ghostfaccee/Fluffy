О проекте

Что такое Fluffy?

Это не просто сайт-одностраничник. Это проект социальной сети, в которой бекенд, фронтенд и инфраструктура взаимодействуют вместе.

Основная идея проекта - создать собственную социальную платформу и последовательно развивать её как самостоятельную систему. В основе Fluffy лежит клиент-серверная архитектура: пользователь взаимодействует с веб-интерфейсом, интерфейс обращается к API, а серверная часть отвечает за обработку запросов и работу с данными.

Проект распространяется с открытым исходным кодом. Это позволяет знакомиться с реализацией, разбираться в структуре приложения, находить ошибки, предлагать улучшения и создавать собственные изменения на основе репозитория.

Проект постоянно находится в разработке. Поэтому опубликованный код и технические материалы стоит рассматривать как отражение текущего состояния проекта, а не как обещание окончательного набора возможностей или завершённого продукта.

Устройство проекта

Из чего состоит Fluffy

За пользовательским интерфейсом находится несколько взаимосвязанных частей. Каждая отвечает за свою область работы, а вместе они образуют приложение.

01

Пользовательская часть

Веб-интерфейс - точка взаимодействия человека с социальной сетью. Он отвечает за отображение страниц, элементов управления и передаёт запросы серверу через API. Клиентская часть построена на Vue.js, а для разработки и сборки используется Vite.

02

Серверная часть

Backend предоставляет API и обрабатывает запросы клиентского приложения. Он написан на Python с использованием FastAPI. Это отдельная часть системы, которую можно запускать и проверять независимо от процесса разработки интерфейса.

03

Хранение и работа с данными

PostgreSQL используется как основная база данных, а Redis входит в инфраструктуру проекта. Для изменения структуры базы предусмотрены миграции Alembic - история изменений схемы хранится в репозитории.

04

Окружение и инфраструктура

Docker Compose помогает запускать компоненты проекта совместно. nginx используется в схеме запуска веб-сайта, а настройки окружения разделены между конфигурационным файлом и переменными среды.

Для разработчиков

Как запустить проект

Основной способ запуска описан в README репозитория. Ниже - краткая последовательность действий, которая поможет подготовить окружение и поднять приложение локально.

Что понадобится

Перед началом убедитесь, что необходимые инструменты установлены.

✓

01

Подготовьте конфигурацию

Скопируйте пример переменных окружения. В файле .env нужно заполнить необходимые значения для подключений и секретные параметры. Не добавляйте этот файл в систему контроля версий, так как он хранит конфиденциальные данные. 

cp .env.example .env

Общие настройки приложения находятся в config.yaml, а описание переменных окружения - в .env.example.

02

Запустите сервисы

Docker Compose содержит профили prod и test. Для обычного запуска проекта используется профиль prod. 

docker compose --profile prod up --build -d

Команда собирает необходимые образы и запускает контейнеры в фоновом режиме.

03

Примените миграции

После запуска сервисов примените миграции базы данных, чтобы привести её структуру к актуальному состоянию. 

docker compose --profile prod exec api alembic upgrade head

История ревизий находится в migrations/versions/. Перед изменением схемы ознакомьтесь с руководством по миграциям.

04

Откройте приложение

После успешного запуска веб-сайт и API будут доступны по локальным адресам:

Веб-сайтlocalhost:8080 ↗ APIlocalhost:8000 ↗ Swagger UIlocalhost:8000/docs ↗ ReDoclocalhost:8000/redoc ↗
⌘

Разработка клиентской части

Если backend уже запущен и вы хотите отдельно работать над интерфейсом, перейдите в директорию frontend, установите зависимости и запустите Vite. Адрес локального сервера разработки появится в терминале. 

cd frontend
npm ci
npm run dev

Обратите внимание: профили Docker Compose предназначены для работы и тестирования проекта и сами по себе не являются готовой конфигурацией для полноценного промышленного развёртывания.
