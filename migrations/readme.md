# Рукодводство по миграциям

## Миграции базы данных

В проекте Fluffy для управления изменениями схемы PostgreSQL используется Alembic. Конфигурация находится в файле `alembic.ini`, находящегося в корне проекта. Настройки окружения находятся в файле `env.py`, находящегося в директории `migrations` (вы, кстати, в ней находитесь :) ).
Скрипты ревизий находятся в директории `megrations/versions/`.

## Перед началом работы

1. Выполняйте команды в контейнере `api`
2. Убедитесь, что файл `.env` существует и в нем указаны корректные данные.
3. Проверьте, что изменения применяются к нужной базе данных. По умолчанию команды миграций применяются к той базе данных, которая задана в текущем окружении.
4. Создавайте резервную копию важных данных, если вносите изменения в рабочую базу данных (рабочей базой данных считается база данных из профиля prod в докере).

URL должен быть совместим с асинхронным движком (async engine). Как правило, он будет иметь вид `postgresql+asyncpg://...`.

## Проверка текущей версии схемы

```bash
docker compose --profile prod exec api alembic current
docker compose --profile prod exec api alembic history
docker compose --profile prod exec api alembic heads
```

- `current` — показывает ревизию, зафиксированную в целевой базе данных.
- `history` — выводит список доступных ревизий.
- `heads` — показывает последнюю ревизию (или ревизии) в репозитории.

## Применение существующих миграций

Обновление до последней ревизии:

```bash
docker compose --profile prod exec api alembic upgrade head
```

Обновление на одну ревизию вперед:

```bash
docker compose --profile prod exec api alembic upgrade +1
```

Выполняйте миграции как контролируемый этап развертывания (deployment), а не независимо на каждом экземпляре (реплике) API. Убедитесь, что база данных доступна, а развертываемый код и файлы ревизий соответствуют одному и тому же релизу.

## Создание миграции

1. Внесите изменения в модели SQLAlchemy в директории `app/model/`.
2. Убедитесь, что модель импортирована в `migrations/env.py` — это необходимо для того, чтобы её метаданные учитывались при автоматической генерации миграций в Alembic.
3. Сгенерируйте новую ревизию:

```bash
alembic revision --autogenerate -m "описание изменений схемы"
```

4. Откройте созданный файл в директории `migrations/versions/` и внимательно проверьте его содержимое.
5. Убедитесь, что функции `upgrade()` и `downgrade()` выполняют именно те действия, которые требуются. 
6. Примените изменения к базе данных и проведите тестирование перед фиксацией (коммитом).

Механизм автоматической генерации сравнивает метаданные модели с подключенной базой данных, однако он не способен распознать все семантические изменения. Вручную проверьте ограничения, индексы, переименованные столбцы, преобразования данных, значения по умолчанию на уровне сервера и допустимость пустых значений. В противном случае переименование столбца может быть интерпретировано как удаление старого и создание нового, что приведет к потере данных.

Для изменений, требующих заполнения данными или таких, которые невозможно корректно реализовать с помощью автоматической генерации, пропишите операции миграции вручную.

## Откат миграций (Roll back)

Откат на одну ревизию назад:

```bash
docker compose --profile prod exec api alembic downgrade -1
```

Откат к конкретной ревизии:

```bash
docker compose --profile prod exec api alembic downgrade <revision_id>
```

Возврат к исходному состоянию (удаление всех миграций):

```bash
docker compose --profile prod exec api alembic downgrade base
```

Операции отката могут привести к удалению или изменению данных и зачастую необратимы. Не выполняйте их в рабочей базе данных, не изучив предварительно реализацию метода `downgrade()` в соответствующей ревизии и не убедившись в наличии проверенной резервной копии.

## Docker Compose

Для профиля `prod` примените миграции из контейнера API после того, как база данных будет готова к работе:

```bash
docker compose --profile prod exec api alembic current
docker compose --profile prod exec api alembic upgrade head
```

Для профиля `test`:

```bash
docker compose --profile test exec testapi alembic current
docker compose --profile test exec testapi alembic upgrade head
```

Эти команды используют переменные окружения, доступные внутри соответствующего контейнера. Перед выполнением убедитесь, что переменные `POSTGRES_URL` или `TEST_POSTGRES_URL` указывают на нужную базу данных.

## Текущая история миграций

В репозитории уже присутствуют необходимые ревизии. Используйте команду `alembic history`, чтобы увидеть точные связи между ревизиями и их идентификаторы.
