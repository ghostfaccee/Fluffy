# Как внести вклад в Fluffy

## Ошибки и предложения

Посмотрите [открытые и закрытые задачи](https://github.com/ghostfaccee/Fluffy/issues?q=is%3Aissue), прежде чем создавать новую. Для обычных ошибок и предложений используйте [формы GitHub](https://github.com/ghostfaccee/Fluffy/issues/new/choose). Если проблема связана с безопасностью, следуйте [политике безопасности](SECURITY.md). При общении соблюдайте [кодекс поведения](CODE_OF_CONDUCT.md).

## Локальная разработка

1. Сделайте форк репозитория и создайте рабочую ветку от `main`. Крупные изменения лучше сначала обсудить в задаче.
2. Настройте окружение по разделу ["Быстрый старт"](README.md#быстрый-старт). Храните локальные настройки и секреты в `.env`; не добавляйте этот файл, токены, дампы БД или пользовательские данные в коммиты.
3. Если меняете схему базы данных, добавьте ревизию Alembic и проверьте её на локальной базе по [руководству по миграциям](migrations/readme.md).

## Проверки перед pull request

Для бэкенда настройте тестовое окружение по [руководству по тестам](tests/readme.md) и запустите из корня репозитория:

```bash
docker compose --profile test up -d --build
docker compose --profile test exec testapi pytest -v
```

Для фронтенда используйте Node.js `^22.18.0` или `>=24.12.0`:

```bash
cd frontend
npm ci
npm run build
```

Откройте pull request в `main`. Опишите, зачем нужно изменение, что поменялось и как вы это проверили. Если есть связанная задача, укажите её номер; для изменений интерфейса приложите скриншоты, если они помогают понять результат.

GitHub автоматически подставит [общий шаблон](.github/PULL_REQUEST_TEMPLATE.md). Чтобы выбрать [шаблон исправления ошибки](.github/PULL_REQUEST_TEMPLATE/bug_fix.md) или [шаблон новой возможности](.github/PULL_REQUEST_TEMPLATE/feature.md), добавьте к URL страницы создания PR параметр `template=bug_fix.md` или `template=feature.md` соответственно (`?`, если это первый параметр, или `&`, если параметры уже есть).
